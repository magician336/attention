# 统一实际投入与里程碑策略

## 背景

手动补记、日程确认和计时器结算都产生实际投入，但三者对时间事实的表达不同。若入口各自计算经验或里程碑，重试、编辑、恢复和 Room 持久化就可能把同一段投入重复奖励，或用错误的时间覆盖历史事实。

## 决策

1. **统一触发条件**：只有归入未归档目标的 `TimeEntry` 才产生每分钟 1 点基础投入经验；未归属活动不产生基础经验。父目标汇总只用于进度和统计，不复制基础经验。
2. **规划日评估**：里程碑候选按实际投入记录的 `planningDate` 评估。手动补记和日程确认评估各自记录的规划日；计时器按规划日界线拆分后，对每个受影响规划日评估一次。跨日计时不能把一个日期的投入奖励到另一个日期。
3. **显式 command 时间**：领域 command 接收调用方提供的 `now`，只用它写入新里程碑的 `achievedAtEpochMillis`。不得在领域规则中读取系统当前时间；因此重试和测试可复现，历史编辑仍按记录原有规划日评估。
4. **稳定实例键**：里程碑由稳定的 `instanceKey` 去重。再次执行同一 command、Room 重试、恢复或备份合并都不得创建相同实例；已发放里程碑保留，删除时间记录也不撤回奖励。
5. **适配层边界**：涉及实际投入变化或计时结算的 `AttentionViewModel`、Room、备份和计时服务只提交 typed command、保存 command 结果或重建派生经验。适配层不得自行计算基础经验、判断里程碑条件或发放里程碑；Room 写入和回滚必须覆盖时间记录、里程碑与经验。计时暂停、恢复和崩溃恢复只改变计时状态，不产生或结算实际投入，因此仍可使用现有状态变换路径。
6. **恢复与修复路径**：恢复被删除的时间记录只还原原记录的身份、来源、时间事实和规范化经验，不重新评估或新增里程碑。`awardMilestones()` 仅保留为内部导入/旧数据修复能力，不作为普通页面动作。

## 入口时间语义

| 入口 | `TimeEntry.source` | 规划日 | 精确发生时间 | 里程碑评估 |
| --- | --- | --- | --- | --- |
| 手动补记 | `MANUAL` | command 提供的日期 | 无 | 记录日期 |
| 日程确认 | `SCHEDULE_CONFIRMED` | 日程日期 | 无（保留日程 ID） | 日程日期 |
| 计时器停止 | `TIMER` | 按本地日界线拆分 | 首段开始时间 | 每个拆分日期 |

来源字段和时间戳只描述事实，不改变经验或里程碑规则。

## 验证范围

- 领域回归测试比较三种入口的基础经验、里程碑实例键和显式达成时间，同时检查各自来源时间语义。
- command 测试覆盖重复执行、历史编辑、删除不撤回奖励、恢复保留记录身份和跨规划日计时。
- ViewModel 测试确认入口提交 typed command；Room instrumentation 覆盖 command 持久化、重启规范化和事务失败回滚。
