# 投入经验规范化的领域与适配层边界

## 决策

投入经验的计算规则只有 `:domain` 中的 `AttentionState.recalculateExperience`：目标时间记录的基础经验和已发放里程碑奖励由当前账本与里程碑历史推导。Room、JSON 备份和其他 Android 适配器不得实现另一份经验规则，也不得在适配层发放里程碑。

适配器可以在数据边界调用这个纯领域规范化函数，但用途仅限于修复由持久化格式派生的经验字段：

- `RoomBusinessDataRepository` 在读写事务中以当前实体记录和里程碑重建规范化经验，然后与其他业务数据一起保存。
- `RoomAttentionStateRepository` 在组合业务状态与设置时保留领域结果，不累加或扣除经验。
- `AttentionBackup` 在 JSON 编解码和合并后规范化派生经验，确保备份中的旧值不会覆盖账本事实。

规范化调用不会改变时间记录、目标关系或里程碑集合，也不替代领域命令。所有新增、编辑、删除、计时器结算和里程碑发放仍先由领域规则产生新状态，Room 只在同一事务中持久化该规范化结果。

## 原因

Room 表和 JSON DTO 都保留经验字段以兼容现有边界，但它是可从时间账本和里程碑历史推导的缓存。恢复、迁移或旧数据可能带有过期值；在适配器边界调用同一个纯函数可以修复缓存，同时保持 `:domain` 为唯一规则来源。

## 影响

- 适配器可以防御性规范化派生字段，但不得复制基础经验、等级或里程碑条件。
- 新的经验来源必须先加入领域规则和领域测试，再由适配器持久化其结果。
- Room 与 JSON 测试应验证过期经验值被规范化，而不是把持久化字段当作第二个权威来源。
