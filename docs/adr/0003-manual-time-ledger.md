# T03 手动时间账本的记录边界

## 决策

T03 把手动时间账本定义为对 `时间记录` 的可更正操作：

- 新增记录使用当前选定的规划日，时长以正整数分钟表示，可归入一个未归档目标或保持为未归属活动。
- 编辑只允许修改时长、目标归属和备注，保留规划日、来源、发生时间和稳定 ID。日期错误通过删除后重新记录修正。
- 删除只移除时间记录；目标进度、统计和基础投入经验由当前记录集合重新计算。
- 父目标的直接投入只统计直接绑定的记录；子树汇总递归统计后代记录，同一记录只计算一次。
- 未归属活动支持多选批量归入。命令对所选 ID 做全量校验并原子提交；空集合是无操作。
- 归档目标保留历史记录、统计和奖励，但不能接收新记录或新的归入操作；恢复目标后才可继续记录。
- 里程碑实例是奖励历史，由 T16 负责发放与后续规则；T03 的编辑和删除不撤销已发放里程碑。

## 原因

规划日和来源描述记录事实。允许编辑时移动日期或改变来源会把纠错变成重写历史周期，影响周期统计、跨规划日切分和审计理解。把日期纠错限定为删除后重记，规则更容易验证。

批量归入需要面对列表刷新和重复点击。全量校验加事务式原子提交可以避免只归入一部分而界面仍显示整批成功。归档目标的历史可读性与未来写入权限分离，既保留复盘数据，又避免默认隐藏目标继续累积新投入。

## 影响

- 领域函数必须拒绝归档目标，并拒绝不存在或已归属的批量 ID。
- UI 需要显示当前规划日的记录编辑入口，并为未归属活动提供多选、全选和目标选择。
- Room 写路径继续通过单次业务事务保存领域结果；数据库不自行推导父子汇总或奖励。
- T16 若以后支持奖励纠错，必须单独定义里程碑撤销或重放协议，不能隐式改变 T03 规则。
