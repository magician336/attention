# Progress Quest 原生接入与游戏进度边界

## 背景

Attention 已经有以实际投入、投入经验、达成里程碑和等级为核心的成长反馈。产品现在需要接入 Progress Quest 的单人自动冒险体验，同时保持时间账本和投入经验的既有语义。Progress Quest 的原版循环包括角色创建、自动战斗、任务、掉落、装备、商店、升级、死亡和存档；官方手册还规定程序退出后不会继续推进。

## 决策

### 1. 原生重写与参考版本

- 在 Android 中用 Kotlin/Compose 原生重写 Progress Quest 的单人规则和内容，不嵌入 WebView，也不启动外部客户端。
- 以官方 6.4 单人版为行为参考。
- 使用 Progress Quest 名称、中文化后的原版专有名词和单人内容；不实现 Realm、账号、联网和排行榜。
- 关于页保留原作者、版权、许可证和“Android 原生重写”说明。官方许可证要求随软件复制版权与许可声明。

### 2. 游戏与 Attention 成长分开

- 现有 `投入经验`、`等级`、`达成里程碑` 继续只由 Attention 的领域规则产生。
- Progress Quest 新增独立的游戏经验、游戏等级、角色属性、游戏奖励和游戏日志；这些值不写入现有投入经验，也不触发现有达成里程碑。
- 归属具体目标的计时、手动补记和导入时间记录都能产生一次游戏奖励；未归属活动不产生，父子目标汇总不重复。
- 游戏奖励通过按时间记录 ID 和已结算分钟记录的幂等账本发放。时间记录增加分钟时只补差额；时间记录减少或删除时不回滚已发放的游戏奖励。

### 3. 计时器、游戏会话与后台

- 计时器和 Progress Quest 游戏会话是两个独立状态，分别在独立页面展示。
- 两个页面通过小窗互相跳转；游戏页面不嵌入计时器，计时器仍通过自己的页面和通知呈现。
- 游戏会话允许后台运行，使用独立 Android 前台服务和游戏通知；暂停或结束会话才停止推进。
- 应用关闭或游戏会话停止后不补算离线游戏时间，符合原版运行时推进的语义。

### 4. 角色、随机性和保存

- 支持多个角色存档。当前角色接收实际投入产生的游戏奖励；没有当前角色时奖励进入待领取池。
- 游戏会话运行时锁定当前角色；暂停后才能切换角色。
- 使用系统随机数，不承诺事件级重放一致性。
- 复刻原版死亡语义：角色不被删除，但会减少一部分游戏经验。升级、任务完成和退出时自动保存。

### 5. Room、备份和导航

- 游戏角色、游戏状态、装备、背包、任务、日志、奖励账本、待领取奖励和会话状态属于 Room 业务数据；不放入 Preferences DataStore。
- 游戏数据进入现有 JSON 备份。多角色按角色稳定 ID 合并，冲突以导入存档覆盖；备份恢复必须保持游戏数据与 Attention 数据的一致提交。
- 底部导航增加第四项“游戏”，并更新启动入口、上次打开页面和导航验收测试。
- 页面遵循组合根与页面 seam：`workspace-state` 只输出游戏页面状态和动作，Android 服务、Room、备份和权限仍由组合根适配。

## 不采用的方案

- 不把游戏经验并入现有投入经验，避免同一时间形成两套隐含的 Attention 成长结果。
- 不用游戏会话时间伪造 `时间记录`，避免挂机改变实际投入、目标进度和现有里程碑。
- 不做联网 Realm、账号、排行榜、跨设备同步或外部客户端嵌入。
- 不把游戏状态放进 DataStore，也不在 UI、Room 或备份适配器中复制游戏规则。

## 影响

- `:domain` 需要新增独立的 Progress Quest 状态、命令、奖励账本和规则测试；它们与 `AttentionState` 的投入经验规则分开。
- Room 需要新增游戏表、DAO、数据库迁移和事务读写；JSON codec 需要新增版本化字段和稳定 ID 合并逻辑。
- `Workspace`、`LaunchDestination`、设置入口和导航测试需要扩展为四个顶级工作区。
- 游戏前台服务需要独立通知渠道、生命周期恢复和进程重建测试。
- 时间记录编辑/删除不撤销游戏奖励，必须在 UI 和备份说明中明确这是奖励历史语义。
