# ADR-0007：以 Compose 参考实现作为日程页视觉真源

- 状态：已接受
- 日期：2026-10-17

## 背景

Issue #180 的 A 方案先用独立 HTML 原型比较工作台布局。该原型便于快速运行和切换候选方案，但它使用浏览器 CSS、静态数据和独立的字体与布局环境；生产页面使用 Kotlin、Jetpack Compose、Material 3、真实主题令牌和 Android 设备约束。两者之间没有自动的样式映射或像素级验收，因此原型中的颜色、边框、间距和组件默认样式可能在移植时漂移。

规格与票据目前主要验收页面顺序、状态、文案、交互 intent 和数据行为。这些验收可以通过而不代表 Android 页面与原型的像素表现一致。

## 决策

1. HTML 原型继续保留，用于早期布局探索和 A/B/C 方案记录；它不再作为生产页面的最终视觉基准。
2. 为已选的 A 方案提供 Compose debug 参考页面。该页面使用真实 Material 3 主题、共享组件、固定 fake state 和目标设备尺寸，不写入业务数据。
3. 视觉验收以 Compose 参考页面的截图和可观察的主题令牌为准，覆盖浅色、深色、紧凑摘要、时间轴、运行中计时、操作栈和空态。
4. HTML 原型、Compose 参考页面和生产 `AgendaScreen` 必须在对应 Issue 或实现文档中互相链接，并记录原型版本与验收截图的来源。

## 后果

- 原型探索与 Android 视觉验收职责分开，后续不会用浏览器渲染结果推断 Compose 的设备表现。
- Compose 参考页面需要维护一份只读的 fake state 和 debug 入口，但可以直接复用生产主题与组件，减少颜色和尺寸漂移。
- HTML 方案仍然保留快速比较的优点；它的颜色和布局只能作为设计意图，不能单独阻止生产实现偏离。
- 行为测试继续负责语义和交互；截图与主题令牌检查负责视觉一致性，两者不互相替代。
