# Attention v0.1.0

## Problem Statement

用户同时承担工作、学习和生活中的多个目标，很难把可用时间分配到这些目标上，也难以持续记录实际投入。传统待办工具通常只记录“是否完成”，计时工具通常只记录“花了多久”，游戏化工具又容易把注意力转移到复杂的角色、装备和惩罚机制上。

用户需要一个 Android 应用，把长期目标、每日规划和实际投入放在同一个时间账本中：可以从分钟开始记录，自动汇总到日、周、月；目标可以拆成多级结构；现实变化可以调整未来计划并主动迁移剩余目标；真实投入可以获得适度的游戏化反馈，同时保留生活中计划之外的活动记录。

## Solution

Attention v0.1.0 是一个本地优先、完全离线的 Android 时间规划应用。它以“目标时间预算 → 日程安排 → 实际投入 → 周期汇总 → 成长反馈”为核心闭环。

用户可以创建没有目标时长的文件夹式目标，也可以为任意目标节点设置每日、每周、每月或一次性时间目标。目标树支持任意层级，时间记录只归入一个具体节点，父节点自动汇总自身直接投入和所有后代投入。

用户可以在日期菜单中查看某个规划日或所有日期，创建可编辑的日程条目，并选择性填写时间段、预计时长、备注和关联目标。实际投入通过全局计时器或计时器式手动追加产生；日程安排本身不自动计入实际投入。

目标修改只影响指定未来日期或未来周期。已结束周期保存周期快照，当前周期的缺口不会自动结转；用户可以主动把部分或全部缺口迁移到未来周期或日期范围。一次性目标达成后可以追加新的目标阶段。

游戏化只奖励实际投入和明确达成事件：基础投入经验按有效分钟计算，目标周期、连续投入和长期累计投入产生不同级别的里程碑。等级提供成长反馈，不限制核心功能。

## User Stories

### 目标树与目标阶段

1. 作为用户，我想创建一个没有时间目标的节点，以便把它当作文件夹组织其他目标。
2. 作为用户，我想为任意目标节点设置目标时长，以便让父目标、子目标和独立目标都能承担时间承诺。
3. 作为用户，我想把目标嵌套成任意深度的树，以便表达“阅读 → 中国文学 → 红楼梦”这样的层级。
4. 作为用户，我想展开、折叠和移动目标节点，以便快速浏览和重组目标树。
5. 作为用户，我想让目标节点直接接收时间记录，以便记录尚未细分到子目标的活动。
6. 作为用户，我想查看父目标的总投入，以便同时看到父目标直接投入和所有后代目标投入。
7. 作为用户，我想让一条时间记录只绑定一个具体目标，以便同一段时间不会重复产生基础经验。
8. 作为用户，我想把一次性目标拆成多个目标阶段，以便在原阶段完成后继续增加目标时长，同时保留原阶段历史。
9. 作为用户，我想归档目标，以便从默认列表中移除暂时不用的目标，同时保留历史记录、统计和奖励。
10. 作为用户，我想从“已归档目标”页面恢复目标，以便重新使用以前的目标树。
11. 作为用户，我想在归档页面批量删除目标，以便清理不再需要的目标关系。
12. 作为用户，我想批量删除目标时保留时间记录并解除目标关联，以便清理结构时不丢失生活时间历史。
13. 作为用户，我想移动目标从未来日期开始生效，以便历史周期仍显示原父级关系。

### 时间目标与周期

14. 作为用户，我想给目标设置每日时间目标，以便表达每天需要投入的时长。
15. 作为用户，我想给目标设置每周时间目标，以便按周安排长期投入。
16. 作为用户，我想给目标设置每月时间目标，以便按自然月复盘投入。
17. 作为用户，我想创建一次性总量目标并设置可选截止日期，以便管理课程、项目或考试准备。
18. 作为用户，我想让父目标和子目标各自拥有独立目标，以便分别衡量“读书”和“红楼梦”。
19. 作为用户，我想在当前目标周期开始后修改未来目标规则，以便计划能够适应现实变化。
20. 作为用户，我想修改标题、备注、图标、颜色和父子位置，以便持续整理目标而不改变历史时间记录。
21. 作为用户，我想修改目标时长、目标周期或截止日期并指定未来生效日期，以便调整未来承诺而不回写已结束周期。
22. 作为用户，我想查看一个周期的周期快照，以便知道该周期当时使用的目标值和达成结果。
23. 作为用户，我想看到目标缺口，以便知道周期结束时尚未完成的目标量。
24. 作为用户，我想手动迁移当前周期的部分或全部缺口到未来，以便主动重新安排承诺。
25. 作为用户，我想把迁移目标发送到下一个周期或指定日期范围，以便根据现实安排未来投入。
26. 作为用户，我想查看、修改、取消多条独立迁移记录，以便追踪每次重新规划的来源。
27. 作为用户，我想让迁移目标独立显示在基础目标之外，以便知道未来目标中哪些部分来自历史缺口。
28. 作为用户，我想让目标达到目标量后自动达成，以便不用再手动点击完成。
29. 作为用户，我想在一次性目标达成后继续记录时间，以便继续投入不会被目标状态阻断。
30. 作为用户，我想在一次性目标达成后追加新的目标阶段，以便把后续投入变成新的可衡量承诺。
31. 作为用户，我想看到超额投入，以便知道实际投入超过目标的部分。
32. 作为用户，我想让超额投入计入周、月和父目标统计，但不自动抵扣未来周期，以便每个周期的承诺保持清晰。

### 日程与日期

33. 作为用户，我想从日期菜单跳转到任意规划日，以便快速查看过去或未来的安排。
34. 作为用户，我想在日期菜单中选择“所有日期”，以便浏览全部日程条目。
35. 作为用户，我想在具体规划日下新建条目时自动填入日期，以便减少重复输入。
36. 作为用户，我想在“所有日期”视图中新建条目时默认使用今天，并能修改日期。
37. 作为用户，我想创建只有日期和标题的日程条目，以便记录没有固定时间段的备忘事项。
38. 作为用户，我想给日程条目添加可选时间段、预计时长、备注和关联目标，以便同时支持粗略规划与时间块规划。
39. 作为用户，我想把日程条目标记为未完成或已完成，以便记录事项状态。
40. 作为用户，我想让日程完成状态不自动改变实际投入，以便“完成了事项”和“花了多少时间”保持独立。
41. 作为用户，我想创建每日、每周或每月重复日程，以便不用反复创建相同安排。
42. 作为用户，我想让重复日程的每次发生都是独立条目，以便单独修改某天的内容和完成状态。
43. 作为用户，我想停止重复日程的未来生成，同时保留历史条目，以便结束习惯而不删除过去。
44. 作为用户，我想给日程条目设置可选本地提醒，以便按时看到安排。
45. 作为用户，我想让提醒只通知我，不自动启动计时器或改变完成状态，以便保留主动控制。
46. 作为用户，我想设置每日规划日的本地重置时间，默认是 03:00，以便适应晚睡作息。
47. 作为用户，我想设置每周起始日，默认是周一，以便周目标和周统计符合我的习惯。
48. 作为用户，我想按自然月查看月目标和月统计，以便月份边界保持直观。
49. 作为用户，我想让跨越规划日边界的计时自动拆分，以便每天的统计准确。

### 实际投入与计时器

50. 作为用户，我想启动一个全局计时器并选择目标，以便实时记录实际投入。
51. 作为用户，我想暂停、恢复和结束计时，以便处理休息和临时中断。
52. 作为用户，我想通过计时器式界面手动追加分钟，以便事后补记已经完成的投入。
53. 作为用户，我想使用快捷时长按钮或自定义分钟数，以便快速输入 5、15、30 分钟或 1 小时。
54. 作为用户，我想把手动追加和计时器记录同等计入进度、经验和统计，以便两种记录方式保持一致。
55. 作为用户，我想把时间记录归入某个目标或保持未归属，以便记录生活中计划之外的活动。
56. 作为用户，我想批量把未归属活动归入目标，以便事后整理实际投入。
57. 作为用户，我想修改或删除错误时间记录，以便修正记录错误。
58. 作为用户，我想在锁屏、切换应用和返回桌面后继续计时，以便专注时不用保持应用前台。
59. 作为用户，我想从通知栏查看、暂停和结束计时，以便不必打开应用。
60. 作为用户，我想在应用进程被系统回收后恢复计时，以便不因系统行为丢失记录。
61. 作为用户，我想在手机重启后手动选择恢复或结束上次计时，以便避免系统擅自补记时间。
62. 作为用户，我想让同一时间只有一个活动计时器，以便避免重复计算。
63. 作为用户，我想在切换目标时自动保存前一段计时，以便不丢失已经投入的时间。
64. 作为用户，我想让手动记录以分钟为最小单位，计时器按完整分钟结算，以便统计简单一致。
65. 作为用户，我想让跨过 03:00 日界线的计时拆成两条按规划日归属的记录，以便日统计准确。

### 容量与统计

66. 作为用户，我想设置可选的每日时间容量，以便知道当天大致能安排多少时间。
67. 作为用户，我想在有预计时长或时间段的日程超过容量时看到过载提示，以便及时调整安排。
68. 作为用户，我想让无时长日程不占用容量，以便模糊备忘不会制造虚假的过载。
69. 作为用户，我想让目标承诺与已安排日程分开显示，以便同一目标不会被重复计入容量。
70. 作为用户，我想查看日、周和月的目标投入、实际投入、缺口、迁移目标和未归属活动，以便完整复盘时间分配。
71. 作为用户，我想让统计按目标树向上汇总，但不重复计算同一时间记录，以便同时查看细节和全局。
72. 作为用户，我想查看父目标的直接投入与子树投入，以便区分自己直接做的事情和下属目标的贡献。
73. 作为用户，我想看到目标达成率和超额投入，以便判断计划是否合理。

### 游戏化与成长

74. 作为用户，我想让有效目标投入每分钟产生 1 点投入经验，以便奖励规则透明。
75. 作为用户，我想让未归属活动在归入目标前不产生投入经验，以便游戏进度对应明确目标。
76. 作为用户，我想让父子目标汇总不重复产生投入经验，以便经验对应真实时间。
77. 作为用户，我想在完成日目标或 7 个规划日连续投入时获得 +500 普通里程碑，以便获得即时反馈。
78. 作为用户，我想在完成周/月目标、父目标周期或 30 个规划日连续投入时获得 +1,000 大里程碑，以便奖励持续投入。
79. 作为用户，我想在完成长期一次性目标、完整根目标树或 100 个规划日连续投入时获得 +10,000 超级大里程碑，以便奖励重大成果。
80. 作为用户，我想让每个里程碑实例只触发一次，以便修改目标不会重复刷奖励。
81. 作为用户，我想让父目标和子目标各自拥有达成里程碑，但共享同一段时间的基础投入经验，以便层级成果都被看见。
82. 作为用户，我想每累计 100 小时有效目标投入获得累计投入里程碑，以便长期坚持有明确节点。
83. 作为用户，我想在 500 小时后进入更高的累计奖励档位，以便长期投入获得递增反馈。
84. 作为用户，我想看到累计 100–400 小时每百小时 +10,000、500–900 小时每百小时 +20,000、1,000–1,400 小时每百小时 +30,000 的规则，以便理解奖励来源。
85. 作为用户，我想让之后每进入新的 500 小时区间，每百小时奖励再增加 10,000，以便奖励随长期投入增长。
86. 作为用户，我想让等级由累计经验决定，以便看到长期成长。
87. 作为用户，我想按 `500 × n × (n - 1)` 的累计经验门槛升级，以便等级曲线可解释。
88. 作为用户，我想让等级只提供称号、动画或外观反馈，不限制计时、目标、统计和导出，以便游戏化不妨碍使用。
89. 作为用户，我想让未完成计划不扣经验、不降级、不扣血，以便规划工具不会产生惩罚压力。

## Implementation Decisions

- 目标产品为 Android 应用，采用本地优先、完全离线的运行模式；账号、云同步、广告和第三方行为分析不属于 v0.1.0。
- 主要测试 seam 是确定性的 Attention domain engine。它接收领域命令和当前状态，输出新的状态、领域结果和可展示的事件；Android UI、Room/本地文件、通知、后台计时器和系统权限作为适配层。
- 目标树支持任意深度。每个节点可以没有时间目标，也可以有一个当前目标阶段；任意节点都能直接接收时间记录。父目标总投入等于直接投入加所有后代投入。
- 每个时间记录最多绑定一个具体目标，或保持未归属。父目标汇总不创建副本记录。
- 计划支持每日、每周、每月和一次性目标。每日使用可自定义的规划日界线，默认 03:00；每周默认周一开始且可自定义；月周期使用自然月。
- 目标修改按属性分类：标题、备注、图标、颜色和父子位置可立即更新；目标时长、目标周期和截止日期从指定未来日期或周期生效。已开始或结束的周期保存周期快照。
- 目标缺口不会自动结转。用户可以创建一个或多个目标迁移记录，把部分或全部缺口安排到未来周期或日期范围；迁移目标独立显示、可编辑、可取消。
- 一次性目标达成后仍可记录超额投入。用户可以追加新的目标阶段，旧阶段和旧里程碑保留，父目标汇总全部阶段。
- 日程条目必须有规划日和标题，时间段、预计时长、备注、关联目标和提醒均可选。完成状态只有未完成和已完成，完成状态不创建实际投入。
- 重复日程支持每日、每周指定星期和每月指定日期。每次发生生成独立条目；修改某次只影响该次，停止规则只影响未来。
- 每日容量只计算有明确时间段或预计时长的日程条目；目标承诺不再次占用容量；超出容量只提示，不强制阻止或自动重排。
- 实际投入支持全局单计时器和计时器式手动追加。手动以分钟为单位；计时器内部精确到秒，按完整分钟产生投入。后台、锁屏和应用进程回收后可恢复；手机重启后要求用户选择恢复或结束。
- 计时器跨越规划日边界时按本地规划日拆分记录。手动记录默认使用当前选中日期，但可以修改。
- 投入经验按有效目标投入分钟计算，基础规则为 1 分钟 1 点。未归属活动在归入目标前不产生投入经验；父子汇总不重复计算。
- 普通里程碑为 +500，大里程碑为 +1,000，超级大里程碑为 +10,000。里程碑实例只触发一次；父子目标可以分别拥有里程碑，但同一时间只产生一次基础投入经验。
- 累计投入里程碑按有效目标时间累计：100–400 小时每 100 小时 +10,000；500–900 小时每 100 小时 +20,000；1,000–1,400 小时每 100 小时 +30,000；之后每进入新的 500 小时区间，每 100 小时奖励增加 10,000。每个累计节点只触发一次。
- 等级门槛为 `500 × n × (n - 1)`，等级只提供成长反馈，不限制核心功能。未完成计划不扣经验、不降级。
- 目标归档保留历史记录、统计和奖励。归档管理页支持恢复和批量安全删除；删除目标关系时，时间记录转为未归属活动，关联日程解除目标关联，历史奖励保留。
- JSON 是完整恢复格式，包含目标树、目标阶段、时间记录、日程、重复规则、提醒、设置、经验和里程碑；CSV 只导出时间记录和日程用于分析。JSON 导入默认合并并按稳定 ID 去重，也提供清空后恢复；导入前自动备份当前数据。
- 首屏默认是今天工作台，设置中可选择今天、目标树、所有日期、统计或上次打开页面。今天工作台提供日期导航、日程、目标进度、容量、未归属活动和计时快捷入口。
- 首次引导可跳过，包含规划日界线、周起始日、容量、第一个目标和第一条日程的可选设置。

## Testing Decisions

- 测试以用户可观察的领域行为为主，不测试内部类名、数据库表名或 Compose 布局细节。
- domain engine 必须有确定性单元测试，覆盖：规划日界线 03:00、可自定义日界线、周起始日、自然月、跨边界拆分、父子汇总、任意节点直接投入、无目标节点、目标阶段和周期快照。
- 目标规则测试覆盖：每日/每周/每月/一次性目标、自动达成、超额投入、未来生效修改、目标缺口、多个迁移记录、迁移修改/取消、父子独立里程碑和目标移动的历史保留。
- 时间记录测试覆盖：计时器与手动追加等价、分钟精度、单全局计时器、后台恢复、重启后的恢复选择、未归属活动、批量归入目标、编辑/删除记录和跨规划日拆分。
- 日程测试覆盖：日期自动填充、所有日期视图、可选时间段、完成状态不创建投入、重复日程独立发生、停止未来生成、可选提醒和容量过载提示。
- 游戏化测试覆盖：每分钟经验、普通/大/超级里程碑唯一性、累计 100 小时节点、500 小时奖励档位、等级门槛、父子不重复基础经验和未完成不惩罚。
- 数据测试覆盖：JSON 完整往返、CSV 导出、合并导入去重、清空后恢复、导入预览、导入前备份、归档/恢复/批量安全删除后的历史保留。
- Android 适配层使用集成测试验证 Room 或本地存储重启、前台服务与通知栏控制、进程回收恢复、重启选择、提醒调度和权限拒绝路径。
- UI 测试覆盖首屏选择、日期菜单、目标树展开/移动、日程编辑、手动追加、计时器控制、统计筛选、归档管理和导入预览等用户路径。
- 当前仓库没有现有 Android 测试或实现可复用；v0.1.0 需要先建立 domain engine 的测试基础，再实现 Android 适配层。

## Out of Scope

- 云同步、账号体系、多设备协作和服务端 API。
- 广告、行为分析、社交排行榜、好友、团队和公开挑战。
- 复杂 RPG 职业、装备、战斗、金币商店、惩罚和扣血机制。
- 自动应用阻断、网站阻断、屏幕使用监控和防短视频功能。
- AI 教练、自动排程、自动重排和根据容量替用户改变目标。
- 自定义月周期、财务月、季度目标和跨时区协作。
- 多个并行计时器和同一时间自动分摊到多个目标。
- 直接删除已有历史记录的目标；批量删除只删除目标关系并解除关联。
- 把日程完成状态自动转换为实际投入。
- 通过 CSV 完整恢复目标树、经验或里程碑。

## Further Notes

- `CONTEXT.md` 是本规格使用的领域词汇来源；产品文案、事件名称、测试名称和界面标签应优先使用其中的术语。
- 当前仓库尚无 Android 项目骨架。本规格发布的是 v0.1.0 产品和领域行为基线，后续实现可以选择 Kotlin/Jetpack Compose、Room 或等价技术，但必须保持 domain engine 的外部行为。
- 计时器、通知、规划日界线和导入恢复属于高风险边界，优先用最小可运行切片验证，再扩展视觉游戏化。
- 规格发布后应拆成独立任务：领域模型、时间记录闭环、目标树、日程、统计、游戏化、备份恢复和 Android 系统适配。每个任务都应引用本规格并保留可验证的用户行为。
