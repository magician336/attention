[#216](https://github.com/magician336/attention/issues/216)

## What to build

让备份模块成为导入预览摘要的唯一知识归属。用户在导入前看到版本、各类记录数量、总数、设置与活动计时器信息，以及合并或清空后恢复的候选总数和新增数量；这些数字来自同一份 `ImportPlan`，组合根只负责展示。JSON version 1、稳定 ID、导入前快照、状态指纹和恢复语义保持不变。

## Acceptance criteria

- [ ] 预览能正确展示所有现有记录类型的分类计数、总记录数、设置存在性和活动计时器存在性。
- [ ] 合并与清空后恢复使用同一候选状态摘要；预计总数与可能新增数量和最终提交计划一致。
- [ ] 组合根不再枚举备份记录类型、重新计算当前/候选总数或解释协议字段；新增记录类型只需在备份模块增加一次摘要定义。
- [ ] 空备份、重复里程碑、没有设置、没有活动计时器、没有新增记录和有新增记录的预览都能给出正确结果。
- [ ] 无效备份在预览阶段失败，不修改领域状态、不提交候选状态，也不旋转导入前快照。
- [ ] 现有 JSON 导入、CSV 导出、状态指纹、自动备份和最近导入备份恢复行为保持不变；测试断言结构化摘要和用户可观察结果，不锁定中文行文。
